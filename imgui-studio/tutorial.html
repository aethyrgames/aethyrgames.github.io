Building Your First Layout

This page is meant as a walkthrough of ImGui Studio and how to use it. Work through it with the editor open in another tab and you'll come out the other side with a panel you can paste into a real project.

ImGui Studio is a visual builder for Dear ImGui layouts. You arrange widgets on a canvas and it writes the C++ that draws them. The preview isn't a mockup, it's real Dear ImGui compiled to WebAssembly, so what you see is what your program will draw.

The Three Building Blocks

To use ImGui Studio, you need to understand three main building blocks:

  • The Document - a tree of windows and widgets. This is the thing you're actually editing, and everything else is a view onto it.
  • The Canvas - the live preview in the middle. Real Dear ImGui draws it every frame from the Document.
  • The Generated Code - the C++ pane. It's regenerated from the Document as you work, and you can edit it and push your changes back the other way.

The Document is the source of truth. The canvas and the code are both derived from it, so a change in either one ends up in the same place.

Step 1: Start With a Window

Every Dear ImGui widget has to live inside a window, so that's where a document starts. Open the "Templates" panel on the left and click "Blank window", or use the "Windows" menu to add one.

You'll see it appear on the canvas with a title bar you can drag. Drag it wherever you like. The position writes straight back into the Document, so the generated code moves with it.

Note: hold Shift while dragging a window to snap it to the canvas grid. The grid is the one you can see, so the snap lands where you'd expect.

Step 2: Add Some Widgets

There are three ways to get a widget into your window, and they're worth knowing all three because they suit different moments.

  • Drag it from the palette. Grab any widget in the left-hand palette and drop it on the canvas or into the hierarchy. A drop indicator shows you where it will land.
  • Arm a tool, then click. Press B and your cursor is loaded with a Button. Click on the canvas to stamp one. Press B again to cycle through the rest of that family (Small button, Arrow button). V puts you back to selecting. This is the Photoshop tool-letter pattern, so T is text, C is checkboxes, S is sliders, and so on.
  • Use the insert menu. Press / and type a few letters of what you want. There are 60 widget types and this is the fastest way to reach the long tail of them.

Add a couple of things now, e.g., a Text, a Slider float, and two Buttons. Don't worry about where they land yet.

Note: R stamps another of whatever you inserted last. When you're laying out a row of similar controls it saves a lot of trips to the palette.

Step 3: Arrange Them

This is the part that trips people up coming from other UI builders, so it's worth slowing down on.

Dear ImGui uses a flow layout. Widgets stack top to bottom in the order they appear in the Document, and you don't position them with x and y coordinates. There's no dragging a button to the middle of a window, because the concept doesn't exist. What you control instead is order, nesting, and joins.

  • Order - drag rows up and down in the hierarchy panel, or use Ctrl+Up and Ctrl+Down. This is the flow-layout equivalent of nudging something.
  • Joins - by default each widget starts a new line. Select one and press J to join it onto the same row as the widget above it. That's ImGui's SameLine, and it's how you build a row of buttons.
  • Nesting - containers hold other widgets. Select a few things and press Ctrl+G to wrap them in a Group, or drop widgets into a Child, a Collapsing header, a Tab bar, or a Table from the palette.

Try it on the two Buttons you added. Select the second one and press J. They'll snap onto one row.

IMPORTANT: order in the hierarchy is the same thing as order on screen, tab order, and z-order. If something isn't where you want it, move it in the tree rather than looking for a position field.

Step 4: Set Properties

Select a widget and the inspector on the right fills in with what you can change about it. The fields differ per widget, but a few show up nearly everywhere:

  • Label - the text drawn on or beside the widget. Double-click a widget on the canvas to rename it in place, or press F2.
  • Same line - the join from Step 3, as a checkbox rather than a keypress.
  • Item width - how wide the widget should be when it has no explicit size of its own.
  • Colors - per-widget overrides for any ImGui color slot. These emit as matched PushStyleColor and PopStyleColor pairs in the generated code.

A window has its own set on top of that, e.g., "No resize", "No title bar", "Auto resize", and the size and position it opens at.

Step 5: Try It Out

A layout you can't click isn't finished. Hold Space and the canvas goes live: sliders drag, checkboxes tick, buttons press. Let go and you're back in Edit mode with your selection intact.

Holding is usually what you want, since you're just checking one thing. If you'd rather stay in Live mode, press Tab to toggle it properly.

Note: the values you set while poking at Live mode are the preview's own state, not part of the Document. They won't end up in your generated code, so feel free to drag every slider to the end.

Step 6: Take the Code

The C++ pane has been keeping up the whole time. What it shows is what you'd paste into a project: a state struct holding your widget values, and a draw function that emits the layout.

struct MyPanelState
{
    float volume = 0.0f;
    bool muted = false;
};

void DrawMyPanel(MyPanelState& state)
{
    ImGui::SetNextWindowPos(ImVec2(30.0f, 30.0f), ImGuiCond_FirstUseEver);
    ImGui::Begin("My Panel");
    ImGui::SliderFloat("Volume", &state.volume, 0.0f, 1.0f);
    ImGui::Checkbox("Muted", &state.muted);
    ImGui::End();
}

You own the struct. Keep one somewhere that outlives a frame, and call the draw function from your frame loop. The generated code doesn't own any state itself, which is what lets you drop it into an existing project without it fighting whatever you already have.

The pane is editable, and that's not a one-way trip. Type C++ into it, press "Apply", and it parses back into the Document. Anything the tool doesn't recognise is kept verbatim rather than thrown away, so hand-written code around your windows survives a round trip.

Note: Apply rewrites the Document from the text, so anything the parser can't represent will be flagged before it commits. Read the warning if you get one, since that's the tool telling you it's about to lose something.

Going Further

Templates

The Templates panel ships eight worked examples, and they're the fastest way to see how a feature is meant to be put together. "Show and hide windows" is the one to look at if you want one panel to open another. You can save your own too: build something, then save the current document as a template and it'll be there next time.

Clicking a template's + inserts it into whatever you have selected. Dragging it onto the canvas drops it where you let go.

Several Windows

A document can hold as many windows as you like, and each one becomes its own struct and its own draw function. Mark a window "Closable" and it gets a close button plus a bool your code checks before drawing it. Point a Button's "Toggles" property at that window's title and clicking it shows and hides the window.

Function Containers

If a window is getting long, wrap a run of widgets in a Function container. It draws nothing of its own, but the generator lifts its contents into a separate static void that takes the same state by reference, and leaves a call behind in its place. It's a way to keep the emitted code readable without changing what it draws.

Getting Around the Canvas

  • Pan - drag with the middle mouse button, or hold Ctrl+Alt and drag with the left.
  • Zoom - ] and [, or the control in the status bar. Ctrl+Shift+F fits the whole document in view and Shift+F puts you back at the origin at 100%.
  • Guides - drag one out of any ruler to line things up. Double-click a guide to remove it.

Windows can sit at negative coordinates, so you can spread a multi-window layout out in any direction and the sheet will follow you.

Keys Worth Learning

Press ? in the editor for the full list, which is searchable and always current. Every key is rebindable from the same overlay. These are the ones that pay for themselves fastest:

  • Space (hold) - peek at Live mode, release to snap back.
  • J - toggle the SameLine join on the selection.
  • / - insert menu, filtered over all 60 widget types.
  • Ctrl+K - command palette, for anything without a dedicated key.
  • Enter and Esc - descend into a container, and back out of one.
  • Up and Down - walk between siblings. Add Ctrl to move the selection instead of the cursor.
  • Ctrl+G - wrap the selection in a Group. Add Shift to unwrap one.
  • F - centre the selection on screen when you've lost it.
  • Ctrl+Z - undo. Structural edits are easy to fire by accident, so this one gets used a lot.

Saving and Sharing

Your work is saved in the browser as you go, and the tab strip along the top holds several projects at once with an undo stack each. Nothing is uploaded anywhere.

  • Export JSON - writes the whole document to a file you can check into a repo.
  • Import JSON - reads one back.
  • Share - packs the document into a link. The document travels in the URL itself, so whoever opens it gets your layout without anything being stored on a server.
Note: because the browser is doing the saving, clearing site data for this domain clears your projects with it. Export anything you'd be sad to lose.

Where to Go Next

The best next step is to open a template that's close to what you're building and take it apart. Check out "Property inspector" and "Menus and dialogs" for the two shapes most tools end up needing.

We're still iterating on this, so some corners are rougher than others. The ? overlay renders from the same table the app dispatches on, which makes it the accurate answer whenever this page and the editor disagree.
